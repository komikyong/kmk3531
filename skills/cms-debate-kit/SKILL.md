# CMS Debate Kit

도서 발췌문만을 근거로 `발췌문 → 논제 → 근거카드 → 활동지·루브릭 → 인용 검증`의 흐름을 수행한다. 자료의 교육 수준, 수업 시간, 토론 방식, 기존 양식은 사용자가 제공한 조건을 우선한다.

## 작업 전 확인

1. 작업 폴더의 발췌문, 토론 규칙, 기존 양식과 결과물 현황을 읽기 전용으로 파악한다.
2. 생성할 산출물, 사용할 입력 파일, 예상 결과, 파일명과 절대 저장 경로를 먼저 제시한다.
3. 파일 생성·이동·수정은 사용자의 명시적 승인을 받은 범위에서만 수행한다. 승인 전에는 분석과 계획만 한다.
4. 불확실한 사실과 수치는 `확인 필요`로 표시한다.

## 근거와 인용의 절대 규칙

- 논제, 주장, 근거카드, 활동지 예시 답안, 루브릭의 내용 근거는 제공된 발췌문 안에서만 찾는다.
- 발췌문에 없는 외부 지식, 줄거리, 작가 의도, 시대 배경, 통계나 사실을 토론 근거처럼 추가하지 않는다. 사용자가 별도로 요청한 배경 정보도 발췌문 근거와 명확히 분리한다.
- 요청한 내용을 발췌문에서 뒷받침할 수 없으면 추측하거나 보완하지 말고 정확히 `발췌문에서 확인 불가`라고 표시한다.
- 직접 인용은 철자, 띄어쓰기, 문장부호를 포함해 원문 그대로 옮기고 문단 번호를 함께 적는다.
- 원문에 문단 번호가 없으면 번호를 임의로 원본에 삽입하지 않는다. `문단 번호 확인 필요`라고 알리고, 승인받은 경우에만 `결과물` 폴더의 별도 작업 사본에 문단 번호를 부여한다.
- 요약이나 해석은 직접 인용과 구분하고, 어느 인용과 문단에 근거하는지 연결한다.

## 워크플로우

### 1. 발췌문 구조화

- 문단 번호, 핵심 사건·발언·갈등, 등장 관점, 명시된 가치 판단을 정리한다.
- 모든 항목에 출처 문단을 연결한다. 발췌문 밖의 맥락이 필요한 항목은 `발췌문에서 확인 불가`로 둔다.

### 2. 논제 설계

- 발췌문 속에서 찬반 양쪽이 실제로 논증 가능한 가치·정책·사실 논제를 제안한다.
- 논제가 발췌문의 범위를 벗어나거나 한쪽 근거가 부족하면 범위를 좁히거나 부족함을 명시한다.
- 각 논제에 관련 문단과 찬반 양쪽의 근거 가능성을 짧게 연결한다.

### 3. 근거카드 작성

각 카드에는 최소한 다음을 포함한다.

- 논제와 입장
- 핵심 주장
- 원문 그대로의 인용
- 문단 번호
- 인용이 주장을 뒷받침하는 이유
- 예상 반론과 발췌문 기반 대응
- 근거가 부족한 경우 `발췌문에서 확인 불가`

같은 인용을 여러 주장에 기계적으로 재사용하지 말고, 각 주장과 인용 사이의 논리적 연결을 확인한다.

### 4. 활동지와 루브릭 제작

- 활동지는 논제 이해, 근거 선택, 인용 기록, 해석, 반론·재반론, 최종 성찰이 자연스럽게 이어지도록 구성한다.
- 학생이 직접 인용과 해석을 구분해 쓰도록 문단 번호 입력란을 둔다.
- 루브릭은 발췌문 충실성, 인용 정확성, 주장-근거 연결, 반론 대응, 표현·협업 등 실제 활동에서 관찰 가능한 기준으로 작성한다.
- 최고 성취 수준에도 발췌문 밖 지식을 요구하지 않는다. 인용 정확성과 문단 번호 표기를 별도로 검수할 수 있게 한다.

### 5. 인용 및 일관성 검증

최종 저장 전 다음을 항목별로 대조한다.

1. 모든 직접 인용이 발췌문과 글자 단위로 일치하는가.
2. 모든 인용에 정확한 문단 번호가 있는가.
3. 논제와 찬반 근거가 발췌문 범위 안에 있는가.
4. 근거카드의 주장·해석이 연결된 인용으로 실제 뒷받침되는가.
5. 활동지 예시와 루브릭이 근거카드 및 토론 규칙과 모순되지 않는가.
6. 확인할 수 없는 항목에 `발췌문에서 확인 불가` 또는 `확인 필요`가 표시되었는가.

검증 결과는 `통과`, `수정 필요`, `발췌문에서 확인 불가`로 구분하고, 문제가 있으면 해당 산출물·항목·문단 번호를 구체적으로 기록한다.

## 파일 보호와 저장

- 발췌문, 토론 규칙, 양식 등 모든 원본 파일의 내용과 파일명을 수정하거나 삭제하지 않는다.
- 기존 파일을 덮어쓰지 않는다. 수정본이 필요하면 새 파일명으로 사본을 만든다.
- 새 문서, 코드, 표, 검증 리포트는 작업 대상 루트의 `결과물` 폴더에만 저장한다.
- `결과물` 폴더가 없으면 생성 경로를 먼저 알리고 승인을 받은 뒤 만든다.
- 계획에 없던 파일은 건드리지 않는다.

## 완료 보고

완료 후 생성한 파일, 파일별 변경 내용, 저장 절대 경로, 파일 수와 사용자가 검수할 항목을 표로 정리한다. 인용 오류나 미확인 항목이 남아 있으면 숨기지 말고 함께 보고한다.
